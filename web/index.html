Stop your agent contradicting itself.

Long agent sessions pile up superseded facts and bulky tool output, so the model has to reconcile two different values for the same key — and you pay for every token of it. contextgc compiles the transcript down to what's currently true. Deterministic, no API key, no model call.

Your transcript

Write path on. The system prompt now tells the agent to declare its own state changes. Facts it declares are marked declared and are never overwritten by anything a regex guessed. It costs a few tokens per turn and there is no extra model call.
No schema selected. contextgc ships an empty entity schema on purpose — the default it replaced matched prose in unrelated domains. Without one you still get tool compaction and turn retirement, but no state is tracked, because there is nothing telling the compiler what a fact looks like.

Or let the agent declare its own state

Regexes cannot resolve "send it to the new place instead". So the agent can report what it concluded, as a structured side-effect of the turn it was already making — no extra model call, no extra latency.

<contextgc-state>{
  "assert": {"destination_address": "Gate 2"},
  "pin":    {"allergy": "peanut"},
  "revoke": ["order_id"],
  "unsure": {"rider": "maybe west"}
}</contextgc-state>

It tracks what each turn asserted

Entity state is last-write-wins. When a key is re-asserted, the earlier turn is retired instead of competing with the newer one.

destination_address: "Gate 2"
gate_code:          "4921"

It never retires the evidence

If a turn is superseded for one key but is still the only support for another, it stays in the context. Retiring it would hand the model a value with nothing behind it.

retired:            [1, 5]
still required:     turn 2 supports refund_claim
orphaned facts:     none

It compacts tool output without losing the safety bits

Bulk rows are sampled, but any row carrying an allergen, severity, PII, or expiry signal is always kept and the omission is reported.

[inventory: 15 rows. Showing 4.
SAFETY-FLAGGED ROWS RETAINED: [{"name":
 "Peanut Butter 500g", "warning":
 "PEANUT_ALLERGEN"}]  11 non-safety
 rows omitted (truncated=true).]

What this does not do

  • It does not make models reliable. It removes contradictions from the input. It cannot add judgement, and it does not stop a model ignoring a rule you pinned.
  • State tracking is regular expressions. There is no coreference resolution, so a fact expressed only through pronouns ("send it to the new place instead") will not be tracked. Missed extractions are the main failure mode: the state is silently incomplete, not loudly wrong. Extend it with StateDAG.register_entity_schema() for your domain.
  • Token counts are chars/4, not a BPE tokenizer. Treat them as a ratio, not a bill. Exact numbers need tiktoken against your real model.
  • Retired-turn recall is lexical (token, subword and phrase overlap) — not semantic. "What did we decide about billing?" will not find a turn that only says "invoice".
  • Nothing here has been benchmarked against real agent traces yet. The numbers on this page are measurements of your input, not published performance claims.
